## Новая возможность: Объединить обновления с картой проекта

Раздел «Обновления проекта» перенесён во вкладку «Обновления» внутри «Проекта»; отдельный пункт меню убран. В верхней части проекта появилась сводка опубликованной версии с быстрым переходом к вкладке. Выпуск в локальной истории показывает затронутые модули; кнопки открывают карточки модулей. Карточка и панель модуля показывают его версию и ссылку на последнее изменение в истории. Сводка выпуска перечисляет число изменённых модулей, исправлений и новых возможностей только при наличии структурированной записи локальной истории. Старый адрес #updates открывает новую вкладку. Скачивание и локальная проверка ZIP сохранены.

**Зачем:** Архитектура, история модулей и проверка выпусков были разнесены по двум разделам, поэтому связь между изменением и модулем приходилось искать вручную.

**Что изменится для пользователя:** Пользователь видит статус обновления в проекте и переходит между выпуском, историей и затронутыми модулями без смены раздела. При более новом выпуске GitHub интерфейс честно показывает только доступные подтверждённые данные.

**Проверки, описанные автором:**
- npm run build — успешно.
- Браузерный smoke-тест: вкладка обновлений, статус и сводка выпуска, переход к модулю и истории, проверка ZIP, старый адрес #updates, мобильные ширины и темы — успешно.
- npm run test:versions: 3 теста пройдены; npm run test:release: 10 тестов пройдены.
- Python unittest: 40 тестов пройдены, 3 Windows-проверки пропущены на Linux.
- npm run check, npm run check:build, npm run release:check и python scripts/chronicle.py validate — успешно.

**Ограничения и известные проблемы:**
- Состав модулей для выпуска новее установленной Reika неизвестен до появления его структурированной записи в локальной истории.
- Проверка новых выпусков по-прежнему зависит от доступа к GitHub.

**Переход на новую версию:**
- После обновления откройте «Проект» → «Обновления». Старые ссылки #updates продолжают открывать эту вкладку.
