## Новая возможность: История локальной диагностики проекта

Монитор проекта теперь формирует устойчивые идентификаторы находок, сравнивает очередную проверку с предыдущей и различает новые, повторяющиеся и исправленные проблемы. Последние 20 снимков с максимум 80 находками сохраняются атомарно в локальном файле без содержимого исходников и восстанавливаются после перезапуска. В интерфейсе появились три группы находок, переход к связанному модулю и шкала последних проверок. Кнопка «Проверить сейчас» вызывает отдельный защищённый POST-маршрут и действительно запускает сканирование, обходя 30-секундный кэш. Повторное чтение того же снимка не создаёт новое уведомление.

**Зачем:** Прежний монитор показывал только текущее состояние, не сохранял историю проблем и мог возвращать кэшированный результат при ручной проверке.

**Что изменится для пользователя:** В разделе «Проект» видно, какая проблема появилась впервые, какая остаётся и какая исчезла. Ручная проверка сразу обновляет результат; история доступна после перезапуска Reika.

**Проверки, описанные автором:**
- Python unit-тесты: переходы находок, сохранение после перезапуска и защита ручного API — успешно.
- Браузерный smoke-тест: группы находок, история проверок и принудительный POST-запрос — успешно.
- npm run build — успешно.
- Python unittest: 44 теста пройдены, 3 Windows-проверки пропущены на Linux.
- npm run test:versions: 3 теста пройдены; npm run test:release: 10 тестов пройдены.
- npm run check, npm run check:build, npm run release:check и python scripts/chronicle.py validate — успешно.

**Ограничения и известные проблемы:**
- История хранится только на этом компьютере и ограничена 20 снимками; при повреждении локального файла история начинается заново.
- При количестве более 80 находок краткая история частичная, что явно отмечается в интерфейсе.

**Переход на новую версию:**
- После обновления откройте «Проект» и выполните проверку. История появится с первого снимка и будет пополняться при последующих проверках.

## Проверки: Проверять переход к актуальной истории модуля

Браузерная проверка перехода из модуля в историю больше не предполагает, что последним изменением всегда остаётся выпуск 0.17.0. Тест читает версию из ссылки модуля и подтверждает открытие именно соответствующего выпуска. Это позволяет проверить то же поведение после добавления новых релизов.

**Зачем:** Кандидат следующего выпуска добавил новое изменение модуля, из-за чего жёстко заданная версия в тесте ошибочно блокировала публикацию.

**Что изменится для пользователя:** Автоматический выпуск не останавливается из-за устаревшего ожидания в браузерном тесте; переход к действительной истории модуля продолжает проверяться.

**Проверки, описанные автором:**
- Локальный браузерный тест пройден на текущей версии 0.21.0.
- Пройдены 47 тестов Python (3 пропущены) и валидация Chronicle.

**Ограничения и известные проблемы:**
- Изменение касается теста; поведение интерфейса не меняется.

**Переход на новую версию:**
- Действий пользователя не требуется.
