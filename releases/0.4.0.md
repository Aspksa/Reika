## Новая возможность: Автоматические выпуски и понятная карта модулей

Добавлена система подготовки выпусков для всего проекта. Она определяет владельцев изменённых файлов, проверяет русские описания работы, рассчитывает общий номер и номера затронутых модулей, собирает интерфейс и сохраняет подробную историю. В разделе «Проект» видны назначения компонентов, версии, типы связей, причины зависимостей, входящие связи и полные описания изменений. Новые модули регистрируются через общий реестр; более точный путь позволяет выделить часть ядра в самостоятельный компонент. Для новых дизайнов поддерживаются отдельные записи об изменениях, растровые изображения и шрифты в готовой сборке.

**Зачем:** Проект будет расширяться: появятся новые функции, самостоятельные модули и варианты оформления. Учёт должен охватывать их автоматически и объяснять изменения понятным русским языком.

**Что изменится для пользователя:** Появился раздел «Проект», где можно выбрать модуль и увидеть связанные части. Версии готовятся автоматически после слияния описанных изменений. Готовый выпуск публикуется только после проверок Windows, Linux, Node.js и браузера.

**Проверки, описанные автором:**
- Локально пройдены девять проверок планирования и подготовки выпусков, три проверки команд версий и двадцать проверок Python. Два теста Windows запускаются в GitHub Actions.
- В изолированном Git checkout проверены подготовка согласованного кандидата, сохранение русских описаний и повторный запуск без создания ещё одного выпуска.
- Проверены сборка Vite, соответствие готовых файлов исходникам и синтаксис JavaScript. Дополнительная браузерная проверка покрывает страницу проекта, фильтр связей и обновление CSS в режиме разработки.

**Ограничения и известные проблемы:**
- Смысл изменения и известные ограничения сообщает автор записи. Автоматика проверяет структуру и тесты, но не может доказать отсутствие всех ошибок.
- Регистрация описывает модуль и его связи; она сама по себе не создаёт его функциональность.
- Для публикации стандартному токену workflow требуется право записи содержимого и возможность обычного продвижения main. Защищённую ветку система не обходит.

**Переход на новую версию:**
- Полностью распакуйте новый архив и запустите Reika.bat. Установка Node.js нужна для разработки сайта, а готовая сборка запускается через Python.
- Другие агенты должны читать AGENTS.md и добавлять отдельную русскую запись в .changes для своей задачи.

## Исправление: Согласованное получение файлов запуска из Git

Для BAT и PowerShell отключено автоматическое преобразование переносов строк Git. Эти файлы уже хранятся с нужными байтами CRLF и UTF-8 BOM для PowerShell; повторное преобразование могло заставить Git считать только что полученную папку изменённой. В сообщение проверки чистоты добавлен список отличающихся файлов, чтобы причина остановки была видна сразу.

**Зачем:** Первый запуск автоматического выпуска остановился на проверке чистоты checkout. Публикация не выполнялась.

**Что изменится для пользователя:** Файлы запуска сохраняют одинаковые байты в архиве и Git checkout, а диагностика подготовки выпуска стала понятнее.

**Проверки, описанные автором:**
- Проверки приложения на Windows, Linux, Node.js и в браузере прошли до исправления; автоматический выпуск будет повторён после этой правки.

**Ограничения и известные проблемы:**
- Система по-прежнему останавливает выпуск при действительно изменённых файлах; проверка чистоты не отключается.

**Переход на новую версию:**
- Дополнительные действия пользователя не требуются. Workflow будет запущен после слияния исправления.
