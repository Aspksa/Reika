## Новая возможность: Журнал проблем, действий ИИ-агентов и точных связей коммитов

Добавлен самостоятельный Project Chronicle: журнал событий проблем с контролируемыми состояниями и историей повторного открытия, учёт заявленных действий ИИ-агентов, просмотр связей коммитов с задачами на основании явных трейлеров в сообщениях Git. История коммитов релиза больше не назначает каждому коммиту все задачи выпуска автоматически. Добавлены проверки и инструкция для других агентов.

**Зачем:** Для работы нескольких ИИ-агентов важно отличать реальные связи с исходным кодом от предположений, хранить историю диагностики и воспроизводимые подтверждения исправлений.

**Что изменится для пользователя:** Можно фиксировать ошибки и действия агентов через консольные команды, просматривать подтверждённые по сообщениям коммитов связи и находить коммиты без задачи. Старый порядок нумерации и публикации релизов сохраняется.

**Проверки, описанные автором:**
- Добавлены автоматические модульные тесты жизненного цикла ошибок, журнала агентов и отсутствия ложных привязок к коммитам. Их выполнение проверяется в GitHub Actions.
- Добавлена проверка структуры журнала Chronicle в CI на поддерживаемых операционных системах.

**Ограничения и известные проблемы:**
- Записи событий отражают отчёт агента, но не подтверждают его личность и фактическое исполнение без независимого свидетельства.
- Старые коммиты без трейлеров не получают искусственно придуманных связей с задачами.
- Локальный журнал необходимо передавать через Git или другой согласованный канал для совместного использования агентами.

**Переход на новую версию:**
- После обновления прочитайте CHRONICLE.md и добавляйте трейлер Task-Id, Fixes-Id либо Refs-Id в новые сообщения коммитов.
- Для сохранения истории агентских событий переносите файл .chronicle/events.jsonl в другую установку или включайте его в Pull Request после проверки конфиденциальности.
