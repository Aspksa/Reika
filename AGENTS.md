# Работа над Reika

- Пишите интерфейс и описания изменений по-русски. Используйте нейтральные обозначения владельца.
- Каждое изменение кода, дизайна, документации или настроек сопровождайте новой записью `.changes/<id>.json` по правилам README. Один id относится к одной задаче; записи других агентов не переписывайте.
- Обязательны: вид изменения, полное описание, причина, влияние на пользователя, затронутые компоненты, фактически проведённые проверки, известные ограничения и порядок перехода. Не выдавайте запланированные проверки за выполненные.
- Номера существующих компонентов и проекта повышает автоматический выпуск. В рабочем PR не меняйте номера вручную.
- Для нового модуля зарегистрируйте уникальный id, русское назначение, статус, начальную версию 0.1.0, пути и связи в versions.json. Более конкретный путь может выделять новый модуль из родительского раздела. Неразмеченные пути и циклы обязательных связей недопустимы.
- Для каждой связи укажите её тип и объяснение. Повышение зависимых версий включается явно через propagate; наличие связи само по себе не доказывает необходимость повышения номера.
- Изменяйте исходники сайта в web; после изменения исходников или метаданных выполняйте npm run build. Сохраняйте новую сборку и каталог файлов вместе с исходниками. Удаляйте старые сгенерированные ресурсы.
- Перед завершением выполните npm run check, npm run test:versions, npm run test:release, npm run check:build и подходящие проверки Python. После последней правки обновите каталог командой npm run build.
- Для проверки описания относительно ветки назначения используйте npm run release:check -- --base <полный SHA>. Публикацию выполняет workflow после проверки именно подготовленного коммита на Windows, Linux и в браузере.
