# Reika · Рэйка Амацухара

Локальное пространство с русским интерфейсом, запуском одной кнопкой и управлением из трея Windows. Первая версия — рабочая основа проекта: главная страница, состояние системы и журналы. Чат и модели пока не подключены.

## Запуск в Windows

1. Скачайте архив вида **Reika-X.Y.Z.zip** из последнего [выпуска GitHub](https://github.com/Aspksa/Reika/releases) и полностью распакуйте его.
2. Дважды нажмите **Reika.bat**. Права администратора не нужны.
3. Дождитесь появления значка Reika возле часов. Браузер откроется автоматически; консоль скроется после готовности трея. Значок может находиться под стрелкой скрытых значков Windows.

Начиная с Reika 0.21.0 готовый архив выпуска для **Windows x64** содержит официальный встроенный Python 3.12.10 в `.runtime\python`; отдельно устанавливать Python не нужно. Более ранние выпуски и архив **Code → Download ZIP** содержат только исходники и требуют установленного Python 3.10 или новее. При запуске проверяются локальный `.runtime\python\python.exe`, `.venv\Scripts\python.exe`, затем `py -3`, `python` и `python3`. Нерабочий кандидат пропускается. Для запуска из исходников официальный Python можно скачать с https://www.python.org/downloads/windows/ .

Для запуска готовой сборки нужен встроенный PowerShell Windows. Node.js используется при разработке и сборке интерфейса; собранные файлы уже включены в архив. Ключи API и платные сервисы для основы не требуются. При запуске скрипты ничего не скачивают и не устанавливают автоматически.

Папку проекта можно переместить на другой диск. Запуск рассчитан на пути с пробелами, кириллицей, `&`, `!` и скобками; рабочая папка определяется по расположению файлов проекта.

## Управление

В меню значка Reika:

- **Открыть Reika** — открыть локальную страницу в браузере. Работает и двойной щелчок по значку.
- **Показать консоль / Свернуть в трей** — управлять окном запуска.
- **Открыть журналы** — открыть папку `logs`.
- **Завершить Reika** — остановить сервер и убрать значок.

Закрытие вкладки браузера оставляет приложение работающим. Повторный запуск `Reika.bat` откроет существующий экземпляр из той же папки. Если трей не смог запуститься или неожиданно завершился, консоль останется видимой; выйти можно через **Ctrl+C**. При ошибке окно запуска не закрывается автоматически.

Дополнительные режимы доступны через тот же файл:

```bat
Reika.bat --diagnostics
Reika.bat --no-browser
Reika.bat --no-tray
Reika.bat --check
```

`--diagnostics` включает подробный журнал и оставляет консоль открытой. `--no-browser` отключает открытие браузера, `--no-tray` оставляет приложение в консоли. `--check` проверяет файлы, запуск сервера и соединение, затем завершает работу. Его можно использовать без браузера и трея.

## Интерфейс

- **Главная**: живой статус соединения, время работы, версия и быстрые действия.
- **Система**: адрес, время запуска, Python, процесс, состояние трея и пояснения к журналам.
- **О Reika**: имя и текущие возможности проекта.
- Светлая и тёмная темы; выбор запоминается в браузере. На узком экране навигация перемещается вниз. Анимация учитывает системную настройку уменьшения движения.

Показания обновляются раз в пять секунд. При потере соединения страница сообщает об этом. Адрес меняется между запусками: открывайте страницу через BAT или трей, а не через старую закладку.

## Локальный сервер и данные

Сервер привязан только к `127.0.0.1`. Свободный порт назначает и сразу резервирует операционная система. Доступ из локальной сети не включён. Проверяются заголовки Host и Origin; команды управления требуют отдельный ключ запуска. Этот ключ передаётся процессу трея через окружение и не записывается в URL, журнал или файл состояния.

Сервер отдаёт файлы из списка готовой сборки web/dist/build.json и сведения о состоянии. Перед запуском проверяются версия и SHA-256 каждого файла. Исходники CSS, Node.js, файл сборочного списка и карты исходного кода через HTTP не выдаются. Через HTTP нельзя читать файлы проекта, журналов или произвольные пути на компьютере. Это локальное приложение, а не граница защиты от программ, уже работающих от имени того же пользователя Windows.

Служебные файлы находятся в `.runtime`, журналы — в `logs`. Обе папки исключены из Git. Основной журнал ограничен 2 МБ с тремя архивами; журнал подготовки — 1 МБ с одним архивом. Никакой базы данных в основе нет.

Скрипты PowerShell сохранены в UTF-8 с BOM для совместимости с Windows PowerShell 5.1. Преобразование переносов строк Git для BAT и PowerShell отключено, чтобы архив и checkout сохраняли одни и те же байты. BAT содержит только ASCII-команды и использует UTF-8; отложенное раскрытие переменных отключено.

## Автоматические версии, новые модули и история

Главный реестр — **versions.json**. Для каждой части задаются имя и назначение на русском, собственная версия, статус, пути файлов и связи. На странице **Проект** показаны назначения, исходящие и входящие связи и подробная история изменений. Фильтр оставляет выбранный модуль и непосредственно связанные части. Новый зарегистрированный модуль появится в этом списке автоматически; его функциональность нужно реализовать отдельно.

Связи имеют типы: `runtime` — запуск или данные во время работы; `build` — сборка; `design` — оформление; `verification` — проверка; `documentation` — описание. Поле `reason` объясняет связь на русском. `propagate: none` сохраняет независимую версию, а `patch` повышает зависимый компонент при изменении зависимости. Циклы обязательных связей runtime/build и несуществующие цели отклоняются. Вложенный модуль может получить путь внутри родительского: владельцем файла становится самое точное правило. Удаляемый модуль сначала помечается deprecated и сохраняется в реестре для истории.

### Запись для каждого изменения

Создайте `.changes/уникальный-id.json` (id латиницей). Все пояснения обязательны и пишутся по-русски:

```json
{
  "id": "improved-chat-layout",
  "kind": "design",
  "title": "Удобное расположение элементов чата",
  "description": "Подробно опишите новое поведение и какие элементы изменились.",
  "reason": "Объясните проблему, которую решает изменение.",
  "userImpact": "Опишите результат для пользователя приложения.",
  "components": { "frontend": "minor", "styles": "patch" },
  "testing": ["Перечислите фактически проведённые проверки и их результаты."],
  "risks": ["Укажите известные ограничения или отсутствие выявленных ограничений в проверенном объёме."],
  "migration": ["Опишите действия после обновления либо явно укажите, что дополнительные действия не требуются."]
}
```

Виды: fix, feature, design, refactor, docs, test, security, maintenance, new-module, breaking. Повышение указывается как patch/minor/major. Несколько записей для одного модуля объединяются: номер повышается один раз по самому существенному изменению. Пока версия ниже 1.0, major переводит на следующую серию 0.x; после 1.0 — на следующую мажорную версию. Идентификаторы записей не должны повторяться. Проверка сверяет записи с реально изменёнными файлами и определениями модулей, включая удалённые пути. Переименование учитывается как удаление старого и добавление нового пути. Смысл изменения выбирает автор; автоматически вывести его из количества строк нельзя.

```bash
npm run release:check -- --base <полный-SHA-ветки-назначения>
npm run release:plan
npm run build
```

Номера существующих модулей и проекта в рабочем PR вручную не повышайте. Файлы наследуют версию своего компонента; точную редакцию фиксирует SHA-256 в **versions.lock.json**. Для текстов в каталоге переносы приводятся к LF. Каталог не хеширует себя и не включает служебные папки/установленные зависимости. Готовая сборка отдельно проверяется по точным байтам. Версии внешних зависимостей остаются их собственными номерами.

### Подключение нового модуля

Подготовьте JSON-описание и выполните `npm run module:add -- путь-к-описанию.json`. Например, описание будущей памяти:

```json
{
  "id": "memory",
  "name": "Память",
  "description": "Хранит и извлекает контекст разговоров для дальнейшей работы.",
  "version": "0.1.0",
  "status": "experimental",
  "paths": ["reika/modules/memory/"],
  "dependencies": [{"target": "core", "kind": "runtime", "reason": "Получает события и команды от ядра приложения.", "propagate": "none"}]
}
```

Новый компонент начинает учёт с 0.1.0. Затем реализуйте файлы модуля, добавьте запись вида new-module, укажите проверки, соберите сайт и сохраните изменения. Описание для регистрации можно держать вне репозитория; каноническая запись находится в versions.json. Неразмеченные новые файлы и неоднозначные пути отклоняются. Правила действуют для кода, дизайна, настроек, документации и тестов.

### Выпуск после слияния

Workflow **Автоматический выпуск Reika** запускается после push в main или вручную через Actions:

1. Собирает накопленные записи и изменения относительно последнего опубликованного тега. Для первого запуска используется releases/state.json.
2. Готовит отдельный коммит в automation/release-…: версии, архив записей, CHANGELOG.md, полные русские описания releases/<версия>.md, историю releases/history.json, журнал исходных коммитов releases/commits.json, сборку и каталог файлов.
3. Проверяет именно этот коммит на Windows, Linux, Node.js и в браузере. Проверки находятся в той же цепочке workflow: система не рассчитывает на повторный push-триггер от GITHUB_TOKEN.
4. Только при успехе продвигает main обычным fast-forward и создаёт тег одним атомарным Git push. Если main уже изменился, публикация отменяется; следующий запуск обработает накопленные изменения.
5. Публикует GitHub Release с полным русским описанием, ссылкой на проверки и ZIP. Исходники и готовый интерфейс входят в архив. Номер и опубликованный тег не переписываются.

Подготовка выполняется последовательно. Повторная попытка для того же исходного SHA использует того же кандидата. Если тег уже сохранён, но создание GitHub Release прервалось, ручной повтор workflow восстанавливает публикацию по этому тегу. Служебные изменения выпуска сами по себе не создают следующий выпуск. Если защиты ветки запрещают обычную запись токена, workflow сообщит об отказе; обход защиты не выполняется.

Ошибки проверок и результаты попыток доступны в GitHub Actions и артефактах release-plan/release-attempt с ограниченным сроком хранения GitHub. В репозитории постоянно сохраняются русские описания известных проблем из записей, история выпусков и SHA исходных коммитов. Старые выпуски 0.1–0.3 сохранены в CHANGELOG.md; расширенный журнал начинает учёт с включения автоматики. Автопроверка не является доказательством отсутствия любых ошибок.

## Node.js и CSS

В проект добавлены **Node.js + Vite** для сборки сайта и режима разработки. Рекомендуется Node.js 24; минимальная поддерживаемая версия — 22.12. Сборка использует точные версии из `package-lock.json`.

CSS находится в `web/styles/`: `theme.css` — цвета, базовые правила и темы; `layout.css` — боковое меню и расположение; `hero.css` — главный блок; `components.css` — карточки и действия; `details.css` — системные разделы; `responsive.css` — мобильная версия и уменьшение движения. Входной файл — `web/app.css`. Логика интерфейса находится в `web/app.js`.

```bash
npm ci --ignore-scripts
npm run build
npm run check
npm run check:build
```

`build` собирает и сжимает CSS/JavaScript, присваивает ресурсам имена с хешами и создаёт `web/dist/build.json` с SHA-256. Папка `web/dist` хранится в репозитории, чтобы ZIP запускался без предварительной сборки. После изменения исходников нужно выполнить `npm run build` и сохранить исходники и новую сборку вместе. `check:build` пересобирает сайт во временной папке и проверяет соответствие готовых файлов исходникам. GitHub выполняет эту проверку автоматически.

Для работы над сайтом сначала запустите Reika через BAT либо `python run.py --no-browser --no-tray`, затем в другом окне:

```bash
npm run dev
```

Vite покажет адрес среды разработки на `127.0.0.1` и будет обновлять интерфейс при изменениях CSS/JavaScript. При занятом порте выбирается следующий. API состояния и устройства проекта передаётся в запущенное ядро Python; после перезапуска ядра перезапустите `npm run dev`, чтобы получить его новый адрес. Через Vite не проксируются команды управления приложением. Браузер из BAT открывает готовую сборку; для разработки используйте адрес Vite из консоли. После `npm run build` перезапустите обычную Reika, чтобы загрузить новую сборку.

## Разработка и проверка

```bash
python -X utf8 -B run.py --no-tray --no-browser
python -X utf8 -B -m unittest discover -s tests -v
```

На Linux/macOS доступен консольный запуск; меню Windows и BAT используются только в Windows. Автоматические проверки охватывают HTTP, защиту служебных команд, закрытые пути, блокировку повторного запуска, восстановление после принудительного завершения и запуск из папки с кириллицей и специальными символами. Windows-проверка дополнительно разбирает скрипты встроенным парсером PowerShell, запускает BAT из другой рабочей папки и проверяет готовность и завершение процесса трея. Появление значка и управление окном требуют проверки на реальном рабочем столе Windows.

Отдельная проверка интерфейса в GitHub Actions устанавливает Playwright только в окружение CI, проверяет навигацию, темы, буфер обмена, пять размеров экрана и восстановление соединения. Скриншоты доступны в артефакте `reika-interface`. Это инструменты разработки; для запуска Reika Node.js по-прежнему не требуется.

## Обновления проекта

В «Настройках проекта» можно выбрать начальную вкладку, сетку или список модулей, плотность карточек, уровень подробностей и интервал локальной автопроверки. Изменения применяются сразу, сохраняются в текущем браузере и синхронизируются с элементами управления на странице «Проект». Автопроверка работает только пока открыт «Проект»; анализ Cloud.ru по-прежнему запускается вручную. Кнопка возврата сбрасывает эти параметры к исходным, не затрагивая тему, уведомления и ключ Cloud.ru.

Во вкладке «Обновления» раздела «Проект» показаны текущая версия, последний стабильный выпуск GitHub и его полное описание на русском. Шапка проекта сообщает, есть ли новая версия. При открытии проекта или нажатии «Проверить обновления» приложение обращается к официальному API Aspksa/Reika. Ответ, включая ошибку, хранится в памяти одну минуту, чтобы ограничить частоту запросов. Без интернета доступная версия не выдумывается: вкладка объясняет ошибку, остальные разделы продолжают работать. Старый адрес `#updates` открывает вкладку «Обновления» проекта.

Ссылка «Скачать» открывает официальный ZIP. Затем выберите скачанный файл на этой же странице: браузер сравнит размер и SHA-256 с метаданными GitHub. Файл никуда не отправляется и не распаковывается. Переименованный ZIP тоже можно проверить. Отсутствие контрольной суммы означает, что проверка недоступна; несовпадение размера или хеша означает, что архив нельзя считать целым. Лимит браузерной проверки — 256 МБ. SHA-256 удостоверяет совпадение с опубликованными байтами и не является цифровой подписью.

История проекта связывает выпуски с затронутыми модулями: из выпуска можно открыть карточку модуля, а из карточки — его последнее изменение. Для опубликованного выпуска краткая сводка модулей показывается при наличии структурированных сведений в локальной истории. Если выпуск новее установленной Reika, до обновления доступны официальное описание и архив без неподтверждённой сводки модулей. Модуль `updates` связан с конфигурацией версий и историей выпусков; ядро предоставляет `/api/updates`. Этот этап включает просмотр и проверку файлов; установка, резервное копирование и откат пока не реализованы.
